Source: owner's third pasted 0.1.0-dev diagnostic report, supplied after the
request to open and close a merchant window without inventory actions. Reported
client: 3.3.5 / build 12340 / Interface 30300 / enUS. Exact source revision and
client modification status remain unverified.

```text
callbackErrors=0
cache generation=1 current=1 valid=true occupied=8 unresolved=0
MERCHANT_SHOW args=0:
MERCHANT_CLOSED args=0:

```
Bag 0 has 16 slots; bags 1..4 have zero slots. Equipment-set count is known zero.
The history includes ADDON_LOADED with one string and PLAYER_LOGIN with no
arguments. There is no last slot probe in this report. These facts are
consistent with fresh initialization, but do not establish whether it came from
reload or login. No sale, purchase or repair operation is reported or inferred.

The actual client delivered MERCHANT_SHOW and MERCHANT_CLOSED with no arguments.
MERCHANT_CLOSED appears twice without reported callback errors. The addon has
no inventory transaction implementation; both events are diagnostic-only. The
observed stable cache shows no merchant-triggered bag scan in this sample.
Repeated close events must remain harmless when services are added later.

## Summary of the basic read-only smoke sequence
Evidence 01..03 covers target startup, known occupied-slot metadata, an empty
slot with zero container returns, bound-positive output on the sampled
Hearthstone, a known empty equipment-set collection, delivered bag/lock events,
a current cache after refresh, READY in the reload/status follow-up, and
merchant open/close delivery. Owner reports provide original-client evidence;
no WoW client was executed in the development environment.

The basic read-only smoke sequence is successful for this reported client.
Broader acceptance remains partial: positive quest/refund/lock-field values,
configured sets, unbound items, uncached data, native report-panel controls,
UI_ERROR_MESSAGE delivery, full logout and additional locales were not verified.
Do not convert these omissions into false values or claim inventory-operation
readiness. No further inventory manipulation is requested to fill these gaps.
No Phase 2 implementation is authorized by this report.
