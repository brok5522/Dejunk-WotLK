# گزارش فاز صفر Dejunk-WotLK

فاز صفر تکمیل شد. هنوز هیچ کد اجرایی افزونه یا عملیات فروش، تعمیر، بازکردن
آیتم و حذف موجودی ساخته یا اجرا نشده است. هدف دقیق پروژه نسخهٔ اصلی
3.3.5a، بیلد 12340، Interface 30300 و Lua 5.1 است؛ Wrath Classic هدف ما نیست.

سورس Dejunk نسخهٔ 3.5.1 در کامیت ثابت
`04bafd5e411441ef5b51bb8ed10d208f2d7758f5` بررسی شد. معماری آن شامل کش کیف،
فیلترهای جداگانهٔ فروش و حذف، چهار لیست، پروفایل‌ها، سرویس‌های عملیات و رابط
تنظیمات اختصاصی است. قابلیت‌های تکمیلی مانند پنجرهٔ آیتم‌های قابل بازکردن،
کلیدهای میان‌بر، ورود/خروج لیست و API عمومی هم در نقشهٔ راه ثبت شدند.

تغییر شمارهٔ Interface کافی نیست. APIهای جدید، خروجی جدولی اطلاعات کیف،
سیستم جدید تجهیزات، تنظیمات و برخی روش‌های ساخت رابط در کلاینت قدیمی وجود
ندارند یا شکل متفاوتی دارند. جایگزین‌های قدیمی با سورس ثابت رابط WotLK مقایسه
شدند. جدول سازگاری مشخص می‌کند کدام مورد شاهد کد دارد و کدام هنوز به آزمون در
بازی نیاز دارد. کتابخانه‌ها نیز صرفاً به‌خاطر نام آشنا سازگار فرض نشده‌اند.

طراحی پیشنهادی، خواندن اطلاعات بازی، تصمیم دربارهٔ آیتم و اجرای عملیات را جدا
می‌کند. اطلاعات ناقص نباید به مجوز فروش یا حذف تبدیل شود. قبل از هر عملیات و
بعد از تأیید پنجره، آیتم، لینک کامل، تعداد و وضعیت اسلات دوباره بررسی می‌شود.
حذف خودکار در پس‌زمینه نخواهیم داشت. فروش و تعمیر خودکار پیش‌فرض خاموش‌اند.
در طرح پیشنهادی Safe Sell پیش‌فرض روشن و محدود به ۱۲ تلاش فروش است؛ حفاظت
آیتم‌های مأموریت، ست تجهیزات و قابل بازپرداخت از لیست‌های شامل بالاتر است.
این تفاوت‌های عمدی با رفتار اصلی، در مستندات انگلیسی توضیح داده شده‌اند.

ساختار پوشه‌ها، AGENTS.md، معماری، سیاست ایمنی، بررسی وابستگی‌ها، برنامهٔ تست،
نقشهٔ راه هشت‌مرحله‌ای از صفر تا انتشار، بررسی خودکار آفلاین و راهنمای بازبینی
GitHub آماده‌اند. پوشه‌های src و tests فعلاً شرح مسئولیت دارند و کد افزونه ندارند.
انتخاب مجوز کد جدید و بررسی مجوز کتابخانه‌ها پیش از توزیع انجام خواهد شد.

بررسی آفلاین، سازگاری واقعی با بازی را اثبات نمی‌کند. این محیط کلاینت WoW ندارد؛
آزمون Lua و آزمون داخل بازی هنوز برای افزونه‌ای که ساخته نشده قابل انجام نیست.
گزارش دقیق بررسی‌های انجام‌شده در [VALIDATION.md](VALIDATION.md) قرار دارد.

برای بازبینی، ابتدا [راهنمای GitHub](REVIEW.fa.md)، سپس
[نقشهٔ راه](ROADMAP.md) و [سیاست ایمنی](SAFETY.md) را بخوانید. فاز بعد فقط
زیرساخت و خواندن اطلاعات خواهد بود. آغاز فاز ۱ منوط به تأیید صریح شماست.
