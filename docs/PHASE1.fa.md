# فاز ۱: زیرساخت فقط‌خواندنی

کد فاز ۱ و بررسی‌های آفلاین آماده‌اند. تأیید نهایی این فاز هنوز به اجرای
نسخهٔ اصلی بازی و دریافت گزارش آن وابسته است. در این مرحله افزونه فقط اطلاعات
کیف را می‌خواند؛ فروش، حذف، تعمیر، استفاده از آیتم و ذخیرهٔ تنظیمات ندارد.

## چه چیزی آماده شده است؟

- تشخیص نسخهٔ 3.3.5 یا 3.3.5a همراه بیلد 12340 و Interface 30300؛ نسخه‌های دیگر غیرفعال می‌شوند.
- خواندن کیف اصلی و چهار کیف همراه، با حفظ وضعیت نامشخص و قفل آیتم.
- زمان‌بندی، تجمیع رویدادهای کیف، تلاش مجدد محدود برای اطلاعات ناقص و توقف هنگام خروج.
- خواندن شناسه‌های ست تجهیزات و ابزار اختیاری بررسی وضعیت اتصال یک آیتم.
- گزارش قابل کپی از APIها، اطلاعات اسلات انتخاب‌شده و شکل رویدادها.
- آزمون‌های واقعی Lua 5.1، بررسی خودکار و ابزار ساخت ZIP تشخیصی.

این نسخه هنوز قوانین تشخیص زباله، پروفایل‌ها یا رابط کامل تنظیمات را ندارد.
هیچ‌کدام از نتایج تست شبیه‌سازی، جای آزمون کلاینت اصلی را نمی‌گیرد.

## نصب برای بررسی فقط‌خواندنی

۱. در پوشهٔ مخزن، ZIP را بسازید:
```sh
python3 tools/package.py work/Dejunk-WotLK-phase1.zip
```
اگر فایلی با همان نام موجود باشد، ابزار آن را بازنویسی نمی‌کند؛ نام جدید بدهید.
برای ساخت بسته نیازی به Lua نیست؛ اجرای تست‌ها Lua 5.1 لازم دارد.

۲. ZIP را باز کنید و پوشهٔ `Dejunk-WotLK` را در پوشهٔ AddOns بازی بگذارید.
مسیر نهایی باید دقیقاً این باشد، بدون یک پوشهٔ اضافی در میان:
```text
World of Warcraft/Interface/AddOns/Dejunk-WotLK/Dejunk-WotLK.toc
```
در صفحهٔ انتخاب شخصیت، افزونهٔ Dejunk-WotLK را فعال کنید. اگر از قبل افزونه‌ای
با همین نام پوشه دارید، ابتدا یک نسخهٔ پشتیبان از همان پوشه بگیرید.

۳. پس از ورود، این فرمان را در چت اجرا کنید:
```text
/djw status
```
روی کلاینت هدف باید READY نمایش داده شود. روی نسخهٔ دیگر، DISABLED انتظار می‌رود.
پیام‌ها فعلاً انگلیسی‌اند تا به پشتیبانی فونت فارسی در کلاینت قدیمی وابسته نباشند.

۴. برای نمونهٔ اسلات اول کیف اصلی:
```text
/djw slot 0 1
```
عدد اول شمارهٔ کیف است: ۰ کیف اصلی و ۱ تا ۴ کیف‌های همراه. عدد دوم جای آیتم
داخل همان کیف است. این فرمان فقط اطلاعات آن اسلات را می‌خواند؛ لازم نیست
آیتم را بردارید یا جابه‌جا کنید. اسلات خالی باید EMPTY و دادهٔ نامطمئن UNKNOWN باشد.

۵. گزارش را باز کنید:
```text
/djw report
```
با Ctrl+A و Ctrl+C متن را کپی کنید و برای بررسی بفرستید. گزارش نام شخصیت یا
حساب و لینک آیتم را ندارد، اما شناسه، تعداد و ارزش آیتم انتخاب‌شده را شامل می‌شود.
اگر پنجره باز نشد، خروجی در چت چاپ می‌شود؛ `/djw probe` هم گزارش را در چت می‌نویسد.
اگر اسلات دیگری را بررسی کنید، گزارش فقط آخرین نمونه را نگه می‌دارد؛ برای چند
نمونه، هر بار یک گزارش جداگانه کپی کنید.

در صورت تمایل، باز و بسته‌کردن پنجرهٔ فروشنده بدون کلیک خرید یا فروش فقط برای
دیدن رویدادها کافی است. برای این بررسی هیچ آیتمی را نفروشید، حذف نکنید، مصرف
نکنید یا از کیف برندارید. تست‌های دارای عملیات موجودی به فازهای بعد تعلق دارند.

## بازبینی و ادامه

تغییرات فاز ۱ روی شاخهٔ `phase-1/read-only-foundation` آماده می‌شوند. این شاخه
از commit فاز صفر ساخته شده است؛ اگر فاز صفر هنوز در GitHub ادغام نشده باشد،
Pull Request به شاخهٔ اصلی هر دو فاز را نشان می‌دهد. برای مرور فقط فاز ۱:
```sh
git diff f644c09...HEAD --stat
git diff f644c09...HEAD
```
عنوان و متن پیشنهادی PR در [PULL_REQUEST_PHASE1.md](PULL_REQUEST_PHASE1.md) است.
پس از ثبت commit محلی، برای ارسال:
```sh
git push -u origin phase-1/read-only-foundation
```
در GitHub Files changed و Checks را بررسی کنید و در صورت رضایت ادغام کنید.
هنوز push، انتشار یا merge خودکار انجام نمی‌شود. فاز ۲ به تأیید جداگانه و
تکمیل شواهد کلاینت نیاز دارد. برای غیرفعال‌کردن این نسخه، تیک افزونه را بردارید؛
فایل SavedVariables برای آن ساخته نمی‌شود.
